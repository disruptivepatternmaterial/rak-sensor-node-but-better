# ADR-0010 — RAK19007 `VDD` source is unresolved

- **Status:** Open
- **Date:** 2026-08-31
- **Tracks:** #102

## Context

The hardware guide previously instructed a coreless RAK19007 to supply 3.3 V from its `VDD` pad
during pack qualification. That was not the setup used for the successful capture: capture 13
used a 3.3 V, 50 mA current-limited bench supply with no base board in the loop
[CITE(bench): `docs/EVIDENCE.md`, capture 13](../EVIDENCE.md).

The available sources conflict:

- RAK's official RAK19007 datasheet says Core-connector pins 17/18 `VDD` are “Generated by MCU
  module,” and repeats that sensor-slot `VDD` is “Generated by CPU module”
  [CITE(datasheet): RAK19007 official raw datasheet, connector tables — CIT-RAK19007-RAW](../CITATIONS.md).
- RAK forum guidance describes a base-board 3.3 V regulator and reports troubleshooting a board
  with the Core removed
  [CITE(prior-art): RAK forum, “USB-C Charger Broke RAK4631 or RAK19007?”](https://forum.rakwireless.com/t/usb-c-charger-broke-rak4631-or-rak19007/13532).
- A third-party manual describes the charger output feeding a step-down regulator
  [CITE(prior-art): RAK19007 manual mirror](https://manuals.plus/rak/rak19007-wisblock-base-board-2nd-gen-manual).

The official connector definition and the troubleshooting narrative cannot both support the
previous unconditional instruction.

## Decision

Until the actual board revision is traced or measured:

1. Do not use coreless RAK19007 `VDD` as a source in a build or qualification procedure.
2. Do not diagnose a charger, regulator, base board, or Core from `VBAT`/`VDD` readings alone.
3. Qualify the RAK9154 data line using the bench-supply setup already measured in capture 13.

This decision removes an unsafe instruction; it does not decide which source describes every
RAK19007 revision.

## Exit criteria

Close this ADR only with one of:

- a RAK schematic/revision notice mapping the relevant physical board's `VDD` source; or
- a recorded, coreless measurement on the relevant base-board revision that identifies the rail
  source without exposing a Core GPIO.
